Database model:
Databse is formed by:
    1. Auth models (from better-auth): User, Session, Account and Verification tables
        and are generated by the better-auth package. We only need to create a migration with the following command:
        npx prisma migrate dev --name init --preview-feature
        and then run the following command to generate the client:
        npx prisma generate
    2. App models:
        a. League table:
            This is to store a list of Competitions attached to a League.
            Only 1 competition belongs to a League, but a League will contain between 0 and * Competitions.
        b. Competition table:
            This is to store all the information related to a Competition:
            Name, Description, Start date, End date, Status, CreatedAt, UpdatedAt, Categories and Judges roles assigned
        c. Category table:
            This is to store all the information related to a Category:
            A category is one of the types INDIVIDUAL, PAIRS, TEAM, JUNIOR INDIVIDUAL, JUNIOR PAIRS, PUZZLE_CHESS
            There could be different number of users in every party for a category.
            For INDIVIDUAL category, it is mandatory that parties are composed maximum by 1 user.
            The information to be stored should be:
            Type, Start Time, End Time, Start date, End date, CompetitionId (where does it belong) and Parties participating.
            Start Time and End Time are the times when the category is going to be held.
            Start date and End date are the dates when the category is going to be held and cannot be outside the competition dates.
            Parties participating is a list of parties that are going to compete in the category.
        d. Party table:
            This table is to store the different parties formed when competing in a category of a competition.
            It should store this information:
            Users in party, categoryId (where does it belong), results (finish time), and points obtained.
        e. RoleAssignment table:
            This table is to store the different roles assigned to a user.
            There are 4 main roles:
            1. Participant: This is the default user role for every one participating in a competition. It does not have any special permissions.
            2. Organizer: This role is the one that is needed to be able to access the create competition form. Enables users to Create, Update and Delete their competitions.
            3. Judge: A user can be judge of a Competition. Organizers can select judges. They only can write Participants finish times.
            4. Admin: This role is administrator of the app and can Create, Update and Delete any field of a competition.
            When a user first login, is assigned a Participant role.
            If a user wants to apply for Organizer role, the user needs to apply for it in a form. And it will be assigned when the organizer accepts the user. So there should be a table to store the requests.
            If a user wants to apply for Judge role in a Competition, the user needs to apply for it in the competitions page.
            There is no possibility a user can apply to Admin role.
            The roles holded by the user should be shown in their profile page.
        f. Request table:
            This table is to store the different requests made by users to be assigned a role.
            It should store this information:
            UserId, Role, Status, CompetitionId (if the request is for a competition)
        g. LeaguePoints table:
            This table is to store the points obtained by each user in each competition inside a League.
            It should store this information: UserId, LeagueId, Total Points
